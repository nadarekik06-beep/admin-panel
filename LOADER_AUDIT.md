# Loader coverage audit — admin panel

Every loading state in the admin goes through `<BrandLoader />` (`components/brand/`, a copy of the
storefront component: keep the two in sync). The tables below are generated by a scan of `app/`,
`components/` and `hooks/`; this header is the summary and the list of deliberate exceptions.

## Coverage

| | Before | After |
|---|---|---|
| Routes with their own `loading.tsx` | 1 / 28 | 28 / 28 |
| Client components fetching on mount, wired to BrandLoader | 17 / 28 | 24 / 28 — the other 4 are layout widgets, listed below |
| Files with async actions, pending state shown with the inline loader | 19 / 27 | 26 / 27 — the other one is a badge count |
| Leftover generic loaders (spinners, text-only "Loading…") | 19 | 0 (remaining grep hits are BrandLoader labels, see below) |

## How loading works now

- **Navigation** — `NavigationLoaderProvider` (root layout) starts the BrandLoader overlay on link clicks,
  `router.push` / `router.replace` and back / forward. On `/login` it is fullscreen; the dashboard layout mounts
  an `area` overlay over the content (sidebar + header stay visible) and the fullscreen one steps aside.
- **Hard page loads** — the overlay is in the server HTML (behind the 150ms delay) until the page registers its
  first fetch.
- **First load of a page** — `usePageLoading(loading)` holds the overlay until the page's first fetch is done,
  then it fades out. Later refetches are in-page.
- **`loading.tsx`** — every segment renders `<RouteLoading area />`, which holds that overlay (no stacking).
- **Never stuck** — 15s safety timeout; 8s for a navigation that never starts.
- **No double loaders** — while the overlay is up, in-page section loaders hide and don't start.
- **In-page refreshes** (filters, pagination, search) — `RefreshCover`: a section loader over that block, old
  content dimmed. Payment requests, campaigns and wallets lists also got the loading flag they were missing
  (they showed "no results" before the data arrived).
- **Buttons** — `Btn` / `SubmitBtn` take `loading`: inline loader over the hidden label (width kept), disabled.

## Deliberate exceptions

- `<option>` placeholders in `BrandProductModal` ("Loading…" while categories load) — a native `<option>` can
  only hold text; the select is also disabled meanwhile.
- `products/[id]/page.tsx` skeleton (`aria-label="Loading product"`) — only visible after the overlay is gone,
  i.e. never on the first load; kept for the in-page product switch.
- `products/[id]/edit` card description "Loading attributes…" — a text hint in a card header while the
  section below shows the BrandLoader.
- Remaining "Loading …" grep hits are BrandLoader `label`s (the admin has no i18n, labels are English).
- `orders/page.tsx:820` — a code comment.
- Not wired to the overlay: `Header`, `Sidebar` (pending-payments badge count), `Notificationbell` (its dropdown
  now shows a section loader), `MediaGallery` (images of a page that already holds the overlay),
  `Usenotifications` (background polling).

## Not covered

- Production build not run: the admin dev server was running on port 3001 (a build would overwrite its `.next`).
  `tsc --noEmit` and lint (core-web-vitals) pass with no new problems.
